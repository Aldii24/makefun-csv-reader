Faster drop-in for make.fun's csv-reader 1.0.0. Same answers on every broken-CSV case, far less CPU.

- `fast.js` reads `cases.json` straight into the memory of a 2.8 KB WebAssembly module (`csv.wat`, generated by
  `gen-wat.mjs`, its base64 written into `fast.js` by `build-wasm.cjs`). The module finds each JSON string's end
  for the shape scan and reads each case's CSV from its JSON-escaped bytes 16 at a time with SIMD, writing the
  rows, columns and errors of csv-reader's answer as JSON bytes, which go to `answers.json` with one `writev` per
  case so a single output region is reused. The CSV text is never decoded to a JS string and no answer tree is
  built. A field's escaped bytes are already valid JSON string content, so they are copied as they stand; only
  the characters csv-reader acts on (`,` `"` LF CR and a leading U+FEFF, in any JSON escape form) are
  recognised, and only `""`, CR inside quotes and stray CRs are rewritten.
- `bytes.js` is the same reading in plain JS, loaded only for a case the module cannot finish (a region too
  small, a malformed escape).
- `solve.js` exports `run(input)`, the same reading on a parsed input; `main.ts` falls back to it for any input
  not of the plain `{text, header}` shape.

Rebuild the module: `node gen-wat.mjs simd csv.wat && node build-wasm.cjs csv.wat fast.js` (needs `npm i wabt`).

## Run it

```sh
node --experimental-strip-types main.ts
```
